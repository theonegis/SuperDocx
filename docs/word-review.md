## 2026-09-09：未保存文档的保存／不保存／取消

- Linux/Electron 的关闭、新建和打开入口共享三选项提示，默认保存，Esc 对应取消。
- 关闭使用带请求标识的主进程／渲染进程确认。保存取消、保存失败、编辑操作忙碌或保存之后仍有新修改时，不批准关闭。
- 打开文件的忙碌锁移到未保存确认之后，避免锁住确认流程内部需要执行的保存。
- 保存确认期间拒绝重复的新建／打开确认，减少重复提示和竞争。
- 原文档另存为取消后，不继续新建，不弹出打开文件对话框。
- `npm run build` 通过。
- `node tests/close-save.mjs` 在实际 Electron 中通过：取消关闭、取消保存、新建／打开前取消保存、文件写入失败保持正文、保存成功后关闭、不保存直接关闭且不改写已保存文件；解包最终 DOCX 核对了本次输入文字。
- 原生对话框在测试中替换为固定选择结果，窗口关闭事件、renderer/preload/main IPC、引擎导出与磁盘写入都使用实际代码。

剩余：浏览器预览仍使用浏览器的确认提示；进程崩溃时的恢复／关闭、操作系统会话结束与真实 IME 中途关闭不在上述通过范围内。全应用审查继续进行。

## 2026-09-09：打开失败后的原文恢复

- 修复先更新文件身份再加载内容导致保存路径与正文不一致的问题：新内容成功加载后才提交文件名及主进程文件句柄。
- 打开过程禁用编辑区并保留原文快照；ZIP／字体准备失败时原文与历史不被替换。
- 引擎已开始替换后报错时重新加载原文快照，恢复未保存标记与保存能力。
- 替换前快照写入本地会话交接存储；若原文恢复也失败，快照保留供重新加载恢复。成功打开或成功回退时清理快照。
- `node tests/open-recovery.mjs` 通过：损坏输入、引擎替换后注入失败、替换与回退均失败，以及重新加载后的内容／文件名／未保存状态恢复。
- `npm run build` 通过。
- `node tests/open-recovery-desktop.mjs` 在实际 Electron 生产构建通过：打开 ZIP 签名正确但内容损坏的文件失败后，保存更新原文件而不是失败文件；检查了原文件 XML 中的新输入和失败文件字节未变。

限制：引擎级替换失败后的快照恢复会重建编辑器内部历史，不能声称撤销历史也保留。此机制是文件切换恢复，不是全面自动保存。浏览器故障注入测试仍观察到已记录的 ResizeObserver 循环警告，布局问题尚未闭环。

## 2026-09-09：标尺布局与评论整体居中

- 诊断发现标尺根据页面测量设置 padding，并反过来影响 max-content 画布宽度，触发亚像素 ResizeObserver 反馈。通过标尺 inline-size containment 切断反馈，没有屏蔽错误事件或替换生产 ResizeObserver。
- 修复自动评论布局将内容宽度容器误判为窄视口、隐藏评论侧栏的问题；桌面文档使用明确的 sidebar 布局。
- SDK 页面缩放只改变视觉尺寸时，外层原宽度导致评论占位重叠／居中失准。现在测量实际页面显示宽度，同步到文档层，再按文档加评论画布的几何中心调整横向滚动。
- 保留 12px 左右留白；普通内容变化且画布／视口宽度不变时不重置用户横向滚动。
- `node tests/layout-diagnostic.mjs` 在标尺 containment 修复后相同触发流程得到 0 个 ResizeObserver 警告。
- `node tests/layout-centering.mjs` 最终通过：真实批注侧栏可见；25%、50%、100%、150%、200%、300% 及缩回 100% 时画布中心误差小于 3px；标尺仍有宽度；1000px 窄视口手动滚动位置在普通 DOM 更新后保留；方向切换无 pageerror。

验证范围为当前 Linux Chrome 中的实际 SDK／React 集成。标尺拖动修改页边距、不同分节混合纸张、物理触控板及长文档性能仍需继续验证；不能将这些通过项扩大为全部布局兼容。
